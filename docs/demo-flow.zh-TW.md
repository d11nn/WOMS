# ORD-DEMO 排程展示流程

本流程使用 `db/migrations/002_seed_demo.sql` 與 `NewDemoMemoryStore()` 的 `ORD-DEMO-1` 到 `ORD-DEMO-9`。Demo 目標是讓 Sales 與 Scheduler 分批操作，展示高優先級排序、交期排序、日產能 waterline、低優先級被延後，以及 Sales 草稿訂單衝突處理。

## Sales 操作批次

1. 先確認 Sales 頁面狀態為「待排程」，月曆 2026-06-03 會顯示 `ORD-DEMO-1` 到 `ORD-DEMO-4`，每張卡片包含客戶、數量與交期。
2. 新增一張高優先級草稿訂單：客戶 `ACME`、產線 `A`、數量 `2500`、交期 `2026-06-03`。
3. 試排後應看到 `PREVIEW-DRAFT` 高亮外框，並進入衝突處理。
4. 在衝突處理中可選「預覽最早完成解法」觀察低優先級訂單如何被延後；或選「取消選取目前訂單」，備註預設為「發生衝突，請修改！」，確認後訂單會進入「需業務處理」。

## Scheduler 操作批次

1. 第一批選取 `ORD-DEMO-1` 到 `ORD-DEMO-4`，從 2026-06-03 開始試排並送出，展示高優先級同日塞滿 10,000 片。
2. 第二批選取 `ORD-DEMO-5` 到 `ORD-DEMO-6`，從 2026-06-04 開始試排並送出，展示低優先級在下一天補入。
3. 第三批選取 `ORD-DEMO-7` 到 `ORD-DEMO-9`，從 2026-06-04 或 2026-06-05 開始試排，觀察交期排序與 2,000 片訂單留下的剩餘產能。
4. 若 Sales 後續插入高優先級 2026-06-03 草稿，Scheduler/Sales 的衝突清單都應提供最早完成解法，並在月曆上以 moved/preview 樣式呈現調動。

## 生產流程

1. Scheduler 從月曆點選已排程訂單開始生產，訂單狀態轉為「生產中」並鎖定當日 allocation。
2. 生產回報可輸入部分完成量；未完成的剩餘量會回到待排程並保留來源關係。
3. 再次排程剩餘量時，月曆應展示子訂單或數量調整標記，用來展示拆批與補排流程。

## 驗證重點

- 高優先級訂單早於低優先級訂單排入。
- 同優先級時依交期與建立順序穩定排序。
- 每日 10,000 片 waterline 正確顯示剩餘或超載。
- Sales/Scheduler 衝突清單都能預覽最早完成解法。
- Sales 取消草稿時可以填備註，預設備註為「發生衝突，請修改！」。
